# Jaune source-hygiene allowlist — consumed by scripts/check-hygiene.sh.
#
# Each non-comment line is "<relpath> <normalised source line>" naming a
# CURRENTLY-COMMITTED occurrence of a forbidden pattern under Jaune/ that is
# deliberately retained. The gate fails on any occurrence NOT listed here, so
# neither a stray dbg_trace or sorry nor a new axiom, opaque, @[extern],
# @[implemented_by], partial def, unsafe or native_decide can enter unnoticed.
#
# Upstream this file carries EXACTLY ONE entry (this branch adds six: two that are
# unproved and say so, one of them not even equal to its definition, and four proved
# ones), and that is the point: TRUSTED.md's
# account of what Jaune does not use is a gate rather than a fact about a
# moment. An entry here is a hole in that account, so adding one is a decision
# to be argued for, not a way to make the gate quiet. If prose trips the gate,
# reword the prose instead — see the false-positive note in check-hygiene.sh.
#
# Keep a justification comment above every entry. When the underlying code is
# removed, delete its entry (the gate warns about stale entries).

# `@[csimp] execFueled_eq_cached` — the one compiled-code substitution in Jaune.
#
# WHAT IT CARRIES. The proposition is `execFueled = execFueledCached`, a fully
# proved theorem, not an assertion. Its proof is `execFueledCachedCore_fst`,
# which chains up from `CalldataCache.get_fst` through `genericCall.stepCached_fst`,
# `MessageOp.stepCached_fst`, `NextOp.stepCached_fst` and `Evm.stepCached_fst`. The
# cache structure itself carries a proof field
# `valid : calldata = key.data.sliceD key.inputIndex key.inputSize 0`, erased by
# code generation, so a cache hit is definitionally accountable to the ordinary
# slice and no cached run can observe a value the uncached run would not.
#
# WHY IT IS ALLOWED RATHER THAN REMOVED. It is the landed fix for the
# depth-1024 one-megabyte calldata retention defect (goal
# `jaune-linux-16gb-memory-v1`): `genericCall.step` evaluated a fresh
# million-byte `Bytes` slice per frame and `execFueled` kept every ancestor's
# copy live, ~32 MB of list cells per live call. Sharing the evaluated slice is
# what makes the former offender run in 0.32 s at 57 MB.
#
# WHY IT IS LISTED RATHER THAN SILENT. `@[csimp]` is the attribute that makes
# the compiled binary run a different function from the elaborated definition,
# and every fixture gate measures the compiled binary. `check-hygiene.sh` is
# the trust surface's gate, so this fact belongs on it. Listing it also means a
# SECOND `@[csimp]` anywhere under the scanned source fails the gate and has to
# be argued for here.
Jaune/Implementation/CachedDriver.lean @[csimp] private theorem execFueled_eq_cached :

# `attribute [implemented_by jumpableCompiled] jumpable` — on this branch only.
#
# WHAT IT CARRIES. Nothing proved. `jumpable` is compiled as `jumpableCompiled`, and
# no theorem says the two are equal. This is the hole in TRUSTED.md's account that
# the header of this file warns about, and it is listed so that the gate keeps
# saying so rather than being quiet.
#
# WHY IT IS HERE. `jumpable`'s own definition is exponential on real contract code
# (one mainnet block did not finish in ten minutes), and the proved linear form
# `jumpdestOk` builds a list as long as the code for every jump. The branch exists
# to run mainnet blocks.
#
# WHAT HOLDS IT INSTEAD. The fixture suites; `#guard`s in `Jaune/Check/Machine.lean`
# comparing `jumpableCompiled` with `jumpdestOk` at every position of codes made to
# be awkward for it; the same comparison on random code in the consumer's tests.
#
# WHAT WOULD REMOVE IT. `jumpableCompiled` written without `while` (a loop the
# kernel cannot unfold) and a proof `jumpable = jumpableCompiled`, as a `csimp`.
Jaune/Machine.lean attribute [implemented_by jumpableCompiled] jumpable

# `@[csimp]` on the four lifts — on this branch only, and proved.
#
# WHAT THEY CARRY. Each proposition is `lift = liftCompiled`, a proved theorem.
# The compiled form takes the `Devm` apart before the core runs and builds the
# result from the parts, where the definition reads a part, runs the core and
# writes the result back into the `Devm` it still holds. The proofs are a case
# split on the `Devm` and on the core's outcome.
#
# WHY THEY ARE HERE. Compiled as defined, the `Devm` holds the machine state
# while the core runs on it, so the state has two owners and no array in it can
# be written where it lies: every write to EVM memory copied all of memory. With
# the step given the machine in its parts (`Jaune/Implementation/CachedDriver.lean`),
# these are what let a write to memory be a write.
#
# WHY THEY ARE LISTED. For the reason the first entry gives: `@[csimp]` makes the
# binary run a different function from the definition, and this gate is where
# that is counted.
Jaune/Machine.lean @[csimp] theorem liftMach_eq_compiled : @liftMach = @liftMachCompiled := by
Jaune/Machine.lean @[csimp] theorem liftMachPure_eq_compiled : @liftMachPure = @liftMachPureCompiled := by
Jaune/Machine.lean @[csimp] theorem liftMachMeta_eq_compiled : @liftMachMeta = @liftMachMetaCompiled := by
Jaune/Machine.lean @[csimp] theorem liftMachMetaPure_eq_compiled :

# `attribute [implemented_by ForkRules.accessDelegationRecorded] ForkRules.accessDelegation`
# — on this branch only, unproved, and NOT EQUAL to the definition.
#
# WHAT IT CARRIES. Nothing proved, and nothing that could be: the compiled form hands back
# a machine whose record of reads holds two more addresses than the definition's does (the
# account a call instruction looks at, and the account whose code runs for it). In every
# other field the two agree, which is not proved either.
#
# WHY IT IS HERE. Before Amsterdam the call instructions record no read of the account
# they call. A consumer that runs blocks on a state known only in part relies on the
# record of reads to notice what it was not given; without these two a called account
# left out of a witness is taken for empty and a valid block comes out invalid, which is
# what happened on a block of mainnet. The compiled form closes that for the consumer
# without touching the definitions the proofs are about.
#
# WHAT WOULD REMOVE IT. The two reads written into the four pre-Amsterdam call arms of
# `MessageOp.step` and their cached twins, as the Amsterdam arms have them, with the
# gas-decrease, state-gas and canonicity proofs about those arms carried across. That
# was started and is not finished: the canonicity proofs take one line each, the four
# `step_*_gasDecreasing_legacy` proofs and the state-gas lemmas after them need the
# recorded machine named and its projections rewritten.
Jaune/Execution.lean attribute [implemented_by ForkRules.accessDelegationRecorded] ForkRules.accessDelegation
